# SVG Studio

The design of record for the Studio's **Visuals** tool: `svg_studio.py`, with `svg_preview.py`, `svg_freeze.py` and `svg_registry.py` (§1). How the tool fits into the Studio is in [studio.md](studio.md).

## The Option 3 model

SVG Studio is a *verse-aware orchestrator*: Option 3 of the original Studio plan (`docs/archive/STUDIO_PLAN.md`, Feature B).

- **What it owns:**
  - the verse workflow: navigate, and know when a file is generator-owned;
  - a faithful SMIL preview timed to the narration;
  - the pipeline glue: save into `web/visuals/`, rebuild the manifest.
- **What it doesn't own:** vector drawing. That is the XML pane, or Inkscape. Deploying is Publish's job.

**Every shipped SVG is generator-owned.** Each `generate_*_svg.py` encodes its geometry in Python and rewrites all of its family's files when re-run. `test_registry` checks that every published verse SVG has a registry owner.

- A *hand-authored* file is one with no owner. None exist today. The editable pane and §3 are the affordances for such files. The pane also takes one-off **Hand-edit anyway** edits to a generated file (§4); §3 never applies to one.
- Both are planned to retire (§8).

## 2. The preview

### 2.1 One URL, two hosts

Everything renders from a local HTTP server, so the embedded window and the system browser show the *same* page. The fallback is "open the same URL in the default browser"; nothing else changes.

`PreviewServer` runs on a daemon thread in the Studio process, bound to `127.0.0.1` on an ephemeral port. It serves:

| Route | Serves |
|---|---|
| `/` or `/preview.html` | The wrapper page (§2.2). |
| `/verse.svg` | The **working buffer**: the pane's current text, not the saved file. |
| `/verse.mp3` | The verse's narration MP3 (§2.4), else 404. `Accept-Ranges: none`. |
| `/state` | `{"gen": <int>, "audio": <bool>, "ref": "Numbers 34:6", "cause": "nav" \| "edit"}` |

- Every response is `Cache-Control: no-store`.
- **`gen`** goes up on every `set_content()`. The studio calls it whenever the pane's text or verse changes: debounced edits (400 ms), verse loads, Replay, a finished generator re-run, Reload from disk and Start from prev. frame.
- **`cause`** is `nav` when the narration should start over, and `edit` for a silent picture swap. Silent swaps are pane edits and following the main window's passage, which would otherwise talk over the main window's playback.

**Threading.** tkinter and the HTTP thread share one lock-guarded snapshot `(gen, svg, audio path, ref, cause)`. It is the entire cross-thread surface.

### 2.2 The wrapper page

- **Layout.** A dark page (`#101018`) with a Replay button, the reference and an error line.
- **Polling.** It polls `/state` every 500 ms. When `gen` changes, it fetches `/verse.svg` and injects it **inline** into `#stage`. Re-inserting inline SVG is the one reliable way to restart SMIL from t=0.
- **Narration.** When `cause` isn't `edit` and the verse has audio, it restarts `/verse.mp3` alongside the picture.
- **Replay** re-injects the last state with audio. Its button dims when the verse has no MP3.

Live reload is therefore:
1. type in the pane;
2. the 400 ms debounce bumps `gen`;
3. the page sees it within 500 ms;
4. the picture is re-injected and replays, silently.

Malformed XML mid-edit is injected anyway; the browser's broken render is honest live feedback. The studio also parses the buffer and shows any XML error in its status line, without blocking the preview.

### 2.3 The pywebview host: process model

`webview.start()` blocks and runs its own WinForms message pump through pythonnet. Inside the tkinter process that would be the event-loop fight of §7.2, so the embedded preview is a **subprocess**:

```
studio (tkinter + PreviewServer thread)
   +-- subprocess: python svg_preview.py --url http://127.0.0.1:PORT/preview.html
         +-- webview.create_window("SVG Studio preview", url, width=1104, height=736)
             webview.start()      # blocks; the process exits when the window closes
```

- **Autoplay.** `run_embedded()` sets `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--autoplay-policy=no-user-gesture-required`, so narration plays on reload without a click. The system browser blocks autoplay until a gesture, which is why Replay exists and why the page swallows `play()` rejections.
- **Exit codes:** 0 when the window is closed, 3 when pywebview is missing or fails to start, 2 for bad arguments.
- **One window.** The studio holds the `Popen`. "Open preview" reuses a live window or spawns one, and closing the studio terminates it.
- **Orphan watchdog.** The subprocess polls `/state` every 3 s, and closes itself after 4 misses in a row (about 12 s), covering a studio killed hard.
- **No IPC** beyond the URL argument; all state flows over HTTP.

The interim main-window stage (`svg_stage.py`) uses the same subprocess-and-server pattern, reparented into a Tk frame.

### 2.4 Narration MP3 resolution

`svg_preview.resolve_audio(book, chapter, verse)` probes `web/audio/<Book>_<c>_<v>.mp3`, the file the audio manifest's `<Book>_<c>_<v>.WEB` key names. It is a filesystem probe, not a manifest read. A verse with no MP3 has no narration in the preview.

### 2.5 Fallback: exact conditions

The studio falls back to `webbrowser.open(url)`, with the same page, live reload and Replay, when:

1. starting the preview subprocess raises `OSError`; or
2. 10 s after spawn (`EMBEDDED_FAIL_WINDOW_MS`), the subprocess has exited with a **nonzero** code. That covers a missing or broken pywebview (exit 3), a missing WebView2 runtime and pythonnet failures. An exit code of 0 in that window is the user closing it, not a failure.

On fallback:
- the studio writes `svg_preview_host = "browser"` with `config.update()`;
- it unticks **Preview in own window**;
- it opens the browser and shows the reason (the last stderr line) in the status line.

Later launches read the setting and go straight to the browser. Re-ticking **Preview in own window** writes `"embedded"` again, so the next "Open preview" tries pywebview. This box is the only way back after a failure.

pywebview is a required package (`requirements.txt`), but the studio never imports it: only the subprocess does.

## 3. "Start from previous verse's final frame"

The **Start from prev. frame** button. It is planned to retire with the other hand-authoring features (§8).

### Scope

- **Applies:** a verse with no registry owner, i.e. a hand-authored sequence.
- **Does not apply:** generator families. They already build cumulatively from their spec. Freezing a generated file and editing on top would fork it from its spec. For a generator-owned verse the button is disabled, in hand-edit mode too, and on load the status line reads `<file> — generator-owned (<family label>); pane is read-only.`

### Inputs and outputs

`freeze_to_base(svg_text: str, from_key: str, new_verse: int | None = None) -> FreezeResult`
- `svg_text`: verse N−1's file content.
- `from_key`: its verse key, e.g. `"Acts_13_4"`, recorded for lineage.
- `new_verse`: N. When omitted, it is the number at the end of `from_key`, plus one.
- `FreezeResult.svg_text`: the new starting document for verse N.
- `FreezeResult.warnings`: human-readable strings for the status line. The warning cases below never raise.

### Algorithm (normative)

It parses with `xml.etree.ElementTree`, with the SVG namespace registered as the default so serialization doesn't prefix every tag.

**Step 1: classify every animation element.** Every `animate`, `set`, `animateTransform` and `animateMotion`, in document order:

| Case | Action |
|---|---|
| `repeatCount="indefinite"` (any element type) | **Keep unchanged.** Perpetual animations (the tabernacle pulse) are steady-state ambience and part of the final frame. |
| `animateTransform` / `animateMotion` (not indefinite) | **Keep unchanged**, and warn that it was not frozen. |
| `additive="sum"`, or a `by=` animation with no final value | **Keep unchanged**, and warn: freezing it needs the animated base value. |
| `<animate>`/`<set>` without `fill="freeze"` | The element snaps back to its base value at the end, so the final frame *is* the base value. **Remove the node**, and warn. |
| `<animate>`/`<set>` with `fill="freeze"` | **Freeze** (step 2), then remove the node. |

**Step 2: the freeze itself.** For a qualifying node on parent `P` with `attributeName="A"`:

1. **Final value.** `V` is the last `;`-separated entry of `values`, else `to`. If there is no `A` or no `V`, warn and keep the node.
2. **Write it.** Set `A="V"` on `P` as a presentation attribute, overwriting any existing `A`. If two nodes target the same `A` on the same `P`, the later one wins, matching SMIL's sandwich model for the non-additive case.
3. **Dash cleanup.** If `A` is `stroke-dashoffset` and `V` is numerically 0, *delete* both `stroke-dashoffset` and `stroke-dasharray` from `P` instead. A fully revealed traced line becomes a plain line.
4. **Timing is ignored.** `begin`, `dur`, `keyTimes`, `keySplines` and `calcMode` don't affect the end state.

**Step 3: demote to a flat base group.** The children of `<svg>` split into `<defs>`, which stay first, and everything else:

- **Base group.** Everything else moves, in order, into `<g class="frozen-base" data-from="…">`.
- **Lineage.** `data-from` is the previous base's `data-from` plus `from_key`, space-separated, so it reads `"Acts_13_3 Acts_13_4"` after two hops.
- **Flattening.** When verse N−1 already has a `frozen-base` group, its children are **hoisted** into the new one, so the base stays one flat group however long the chain is.
- **Husks dropped.** An empty `<g>` (only comments), such as a never-filled overlay, is dropped.
- **Overlay.** An empty `<g id="vN">` follows, holding a comment that asks for new ids to be prefixed `vN-`, so they don't clash with frozen clip ids.

`viewBox`, `width`, `height` and `font-family` on `<svg>` pass through unchanged.

**UI flow.**
- It needs verse N ≥ 2, with verse N−1's file present.
- It asks before discarding unsaved edits.
- It puts the result in the pane, unsaved, refreshes the preview, and lists any warnings in the status line.
- It never writes to disk; Save does.

**Tests.** `test_svg_freeze.py` has one test per table row, plus:
- `set`, document-order and structure cases;
- the flat-base hoist across two freezes;
- round-trips of real generator output: a genealogy verse, a traced tribal-map verse, and the tabernacle pulse.

## 4. The generator registry

### File: `svg_generators.json` (repo root)

JSON, not Python: hand-editable, no import side effects, diff-friendly. `{"_comment": …, "families": [...]}`, with 25 families from 24 distinct generators. An example, one of the two families that split Genesis 11:

```json
{ "label": "Shem to Abram (Genesis 11:10-32)",
  "book": "Genesis", "chapters": [11], "verses": [10, 32],
  "generator": "generate_genealogy_svg.py",
  "spec": [ { "file": "generate_genealogy.py",
              "edit": "G11_KEYS (the names), G11_LINE (ages and years), build_g11_specs() verse specs" } ],
  "kind": "genealogy" }
```

| Field | Meaning |
|---|---|
| `label`, `book`, `chapters` | The family and the chapters it owns |
| `verses` | Optional `[lo, hi]`, when the family owns only part of its chapter (Genesis 11) |
| `generator` | The `generate_*_svg.py` to run |
| `spec` | The files to edit, each with an `edit` note for the human (not parsed) |
| `kind` | The manifest's `kind` for the family's files (`build_manifest.py`) |
| `replay_identical` | Optional. `true` makes byte-identical consecutive verses replay instead of sharing one picture (D17). No family uses it today |
| `_comment` | Optional, ignored |

`svg_registry.py` exposes:

```python
@dataclass(frozen=True)
class FamilyInfo:
    label: str; book: str; chapters: tuple; generator: str
    spec: tuple          # tuple[SpecPointer(file, edit)]
    kind: str | None = None
    verses: tuple | None = None
    replay_identical: bool = False

def owner_of(book: str, chapter: int, verse: int | None = None) -> FamilyInfo | None
```

Pass the verse whenever it is known. Without it, the first family listed for a split chapter wins.

`test_registry` checks four things:
- every generator and spec file exists, and imports;
- no two families claim the same verse;
- every published verse SVG has an owner;
- no retired variant file (translation-suffixed or `.still.svg`) is back.

### UI flow for a generator-owned verse

The banner shows the generator and its spec pointers. The file loads **read-only**, and the status line notes a file that carries the hand-edit marker.

- **Edit spec (durable).** Opens each spec file.
  - It uses the `editor` setting in `config.json` when it is set: a command template such as `code -g {file}`, run through the shell.
  - Otherwise it uses the OS file association (`os.startfile`).
- **Re-run generator.**
  - **Before it runs:** it asks to discard unsaved edits. It scans the family's chapter folders for files carrying the hand-edit marker, and asks for confirmation, listing any it would discard.
  - **While it runs:** it runs `[sys.executable, generator]` from the repo root on a worker thread, with no arguments, so the whole family is rewritten. Each output line goes to the status line.
  - **When it finishes** with exit code 0, it reloads the file and refreshes the preview, unless the pane has unsaved edits.
  - While it runs, the studio is busy: it won't follow the passage, and closing asks first.
- **Hand-edit anyway (one-off).** Unlocks the pane. On Save it inserts, right after the `<svg …>` tag, `<!-- hand-edited YYYY-MM-DD; regenerating via generate_x_svg.py will discard this -->`. The marker is informational (detect and route, never block), and it is what the re-run scan looks for.

A verse with no owner opens straight into an editable pane, with no banner. A verse with no file gets a skeleton instead: a 1024×576 `<svg>` with the house background and Georgia font.

## 5. The verse navigator

- **Pickers.** Book and Chapter pickers, from `books.BOOK_NAMES` and `books.chapters_in`, plus a Verse spinbox from 1 to 176. The spinbox is not bounded by the chapter: the main window clamps the shared passage to WEB's verses, but the spinbox doesn't.
- **One file per verse.** A verse is one file, `web/visuals/<Book>/<ch>/<Book>_<ch>_<v>.svg` (`verse_path()`). There are no variants: WEB is the only translation, and visual files carry no suffix.
- **Not shown yet.** Range files (`Book_c_v1-v2.svg`) and identical copies shared through the manifest are planned (§8).
- **Unsaved edits.** Moving a picker with unsaved edits asks first. "No" puts the pickers back on the verse in the pane.
- **What a move does.** Each move re-checks the registry (verse included), updates the banner, and loads the file and its MP3 into the preview.

## 6. Save and manifest

- **Save only** (also `Ctrl+S`):
  - It validates the XML. On a parse error a dialog offers "Save anyway?".
  - It writes the pane to `verse_path()`, creating the folder, and adds the hand-edit marker in hand-edit mode.
  - A read-only pane saves nothing.
- **Save + manifest** saves, then runs `build_manifest.py` as a subprocess on a worker thread. The status line reports the manifest's key count. The manifest only feeds the web app, so plain Save skips it while iterating.
- **Reload from disk** reloads the file (asking first when there are unsaved edits), for example after editing it in Inkscape.
- **Open in Inkscape** opens the saved file, finding Inkscape on `PATH` or in the two `Program Files` locations. When it isn't found, a dialog offers the download page; the XML pane always works without it.
- **No deploy step.** Saved files ship with the next **Publish** ([architecture.md](architecture.md#deploy)).

## 7. Risks

### 7.1 pywebview on Windows ARM64

pywebview drives WebView2 through WinForms via pythonnet, and pythonnet locates a .NET runtime via clr-loader. On this machine:

- **The chain works.** The venv's Python is emulated x64 (`sysconfig.get_platform()` is `win-amd64`), so the x64 wheels install, and `import webview` works.
- **Both windows rely on it.** The embedded preview runs, and the main window's stage (`svg_stage.py`) depends on the same chain.

The fallback stays as the safety net (§2.5). A broken pywebview costs one failed launch, after which the setting sends the preview to the browser.

### 7.2 tkinter + webview event loops

This is solved structurally: `webview.start()` never runs in the Studio process (§2.3). Inside the Studio, the only concurrency is:
- the HTTP daemon thread reading the lock-guarded snapshot;
- worker threads for generator re-runs and manifest rebuilds, which report back through a `queue` drained by `root.after`.

No tkinter object is touched off the main thread.

What remains is an orphaned preview subprocess if the Studio is killed hard. The §2.3 watchdog closes it after about 12 s without an answer.

### 7.3 SMIL freeze edge cases

§3's table gives each case a normative outcome. The posture: **freeze what the house generators emit; warn and preserve everything else.** A warned element that is still animated looks visibly wrong in the preview, which is where you want to find it.

### 7.4 Smaller ones

- **Autoplay.** The embedded window gets the WebView2 autoplay switch. The system browser blocks audio until a gesture, and Replay is that gesture.
- **SMIL in Chromium.** It is deprecated but supported, and the website depends on it too, so the preview adds no risk of its own.
- **Port and firewall.** The server binds only `127.0.0.1`, and Windows Firewall doesn't prompt for loopback. The ephemeral port avoids clashing with a local dev server.
- **Audio ranges.** `http.server` has no Range support, so MP3s go out whole with `Content-Length` and `Accept-Ranges: none`. Chromium accepts that for verse-length files.

## 8. Planned changes

- **Studio phase 2 (D12).** The hand-authoring features retire, including:
  - Start from prev. frame, with `freeze_to_base` and its tests;
  - editing in the pane.

  The pane stays as a read-only Source view. `svg_is_animated` stays, since the manifest uses it.
- **One web view (S2).** `svg_preview.py` and `svg_stage.py` merge into one `web_view.py`, and "Preview in own window" folds into it. The window takes a parent frame.
- **Shared visuals (D17).** SVG Studio labels a verse "shared with vv16-32" when its picture is a range file or an identical copy, and editing it says it affects the whole run.
- **One visual resolver (S2)** replaces `svg_preview.resolve_audio` and the other two Python copies of the path logic.

See [studio.md](studio.md#phases).

## Resolved questions

The design's original open questions, as the code answers them:

1. **Replay narration on every live reload?** No. Pane edits re-inject silently (`cause: "edit"`), while navigation and Replay restart the narration (`"nav"`). Following the main window's passage is silent too.
2. **Is `os.startfile` on a `.py` a real editor?** Not necessarily, so Edit spec honours an optional `editor` command template in `config.json` (`DEFAULTS["editor"]`, empty for the OS default).
3. **Re-run scope for translation-suffixed families?** Moot: WEB is the only translation. Re-run runs the generator's whole `main()`; per-chapter runs wait for the generator CLI contract ([studio.md](studio.md#generator-cli-contract-planned-s5)).
4. **Warn before a re-run clobbers hand edits?** Yes. The re-run confirm scans the family's chapters for the marker and lists the files it would discard.
5. **A raster export so the PC app can show SVGs?** Moot. The Studio's stage renders SVG and SMIL through WebView2, and there are no raster or still images (D4).
